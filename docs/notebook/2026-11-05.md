## Later the same day

Read the stack's Layer 3 and Layer 4 pages, the glossary, the trusttasks.org registry data, and the OpenVTC TypeScript packages (S02). The main findings: the policy engine is Rego, the stack already uses a zero-knowledge proof for hidden vetting, and real TypeScript libraries exist for TSP and for Trust Tasks.

At the convener's request, the repository became a monorepo of projects (decision 0001). The first thread is now `projects/zk-pdp-fit/`. A straw-man community ride-share, `projects/community-rides/`, was started with a design document, to be built on the OpenVTC TypeScript libraries.

The convener then clarified that the ride-share has nothing to do with zk-pdp (decision 0002). The design dropped its zero-knowledge mode and moved its policies from Cedar to Rego.

The convener pointed to the TrustStackers repositories, the stack's own code (S03). They are GPL-3.0, and the convener doesn't want GPL code here, so they aren't used. Community Rides stays on the Apache-2.0 OpenVTC libraries, and its documents now say plainly that OpenVTC is a separate implementation of the same specs.
